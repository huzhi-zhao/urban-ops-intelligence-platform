# ADR 0009 — 统一报告单元：建模与评分一律落在作业分区，ward 只作展示

> **Status**: Accepted · **Date**: 2026-08-09
> **Relates to**: [ADR 0008](0008-plow-schedule-is-a-plan-not-a-record.md) §4.4

决策：**分析单元统一为 `plow_zone`（作业分区）**。具体地

1. **M1 按分区 × 降雪事件训练**，目标变量是该分区在该事件中的工单量，
   不再按 ward 训练；
2. **BO-6 的评分、BO-8 的推荐都只在分区粒度产生**；
3. `ward` / `neighbourhood` 降级为**展示标签**——可以在图上标、可以在讲的时候说，
   但**不得作为任何数值从分区聚合上去的中间层**；
4. BO-4 的交叉映射表继续做，但它的用途从「换算」缩小为「标注」。

---

## 1. 背景：两套划分互相解释不了三分之二

BO-1 的建模单元原定 `ward`（摘要指定的报告粒度），而 BO-2 的排班顺位
**只存在于 `plow_zone`**。两者之间原本设想有一张「交叉映射表」把预测量换算过去
（ADR 0008 §4.4 仍把它列为承重连接）。

**2026-08-09 实测，这张表做不成换算表**（`scripts.analysis.request_point_in_zone`，
13.4 万件同时带 ward 文本与几何的排班期冬季工单）：

| 方向 | 落在其主导对手方的比例 | 各标签中位 |
|---|---|---|
| ward → plow_zone | **34.1%** | 0.34 |
| plow_zone → ward | **45.4%** | 0.53 |

一个 ward 的工单，只有三分之一落在它最主要的那个作业分区里。两套划分是不同部门
为不同目的画的，谁也不包含谁——**这不是精度问题，是它们本来就不是同一种东西**。

后果很具体：若 M1 按 ward 出预测、BO-6 按分区评分，中间那一步不是查表，
是一次会引入约 **66% 分派误差**的重新分配。而 BO-6 三项因子里最强的一项
（顺位，实测影响 0.300 分数单位）恰好只有分区粒度——**误差正好加在最承重的那条腿上。**

这与 `shift_end` 是同一类问题的不同形态：一个被默认成立、从没人量过的连接。

---

## 2. 决策

### 2.1 分析单元 = `plow_zone`

| | 采用 |
|---|---|
| 建模单元 | `plow_zone` × 降雪事件 |
| 面板规模 | 22 个排班分区 × 59 个排班期事件 = **1,298 格**（`score_collinearity` 已在此面板上跑完） |
| 工单归属方式 | **按点归分区**，`ST_Contains`，不经过任何文本标签 |
| 归属可靠性【指标实测 2026-08-09】 | 空间命中率 **99.9%**（134,123 / 134,258） |
| 顺位可用性 | 原生粒度，**零换算** |

选它的理由只有一条，但足够硬：**这是唯一一个三项因子都原生存在的粒度。**
工单有坐标，坐标能落进分区（99.9%）；顺位本来就在分区上；天气按分区质心取。
三者都不需要跨划分搬运，也就没有分派误差这回事。

反过来说，选 ward 就必须把顺位从分区摊过去——那是把唯一实测独立、影响最大的
因子拿去承担 66% 的误差。

> **`score_collinearity` 事实上已经这么做了。** BO-6 那批「三项独立」的数字
> （最大 `|r| = 0.460`、`r(顺位, 请求量) = +0.017`）之所以成立，正是因为它的
> 请求量因子是按点归分区算的、绕开了 ward。本 ADR 只是把一个**已经在跑的实现选择**
> 升级成显式决策——继续含糊下去，等于让 BO-6 的结论悬在一个没写下来的前提上。

### 2.2 `ward` / `neighbourhood` 的新位置：展示标签

摘要指定在 neighbourhood / ward 报告，这条不变。变的是**它们不再承载数值**：

| 用法 | 允许 | 依据 |
|---|---|---|
| 在地图/表格里标出某分区**主要覆盖**哪些 ward，并写出份额 | ✅ | 映射表带权重，份额是实测数 |
| 描述性统计按 ward 出（各 ward 冬季工单量、逐年趋势） | ✅ | 需求侧单独看不需要跨划分 |
| 把分区的评分/推荐**加权聚合成 ward 的评分** | ❌ | 45.4% 的主导份额，聚合结果无法解释 |
| 把 ward 的预测量**摊到分区** | ❌ | 34.1%，误差加在最承重的腿上 |

判据一句话：**标签可以贴，数不能搬。**

`neighbourhood`（237 个，casefold 后）同理，且它比 ward 更细、单元更小，
跨划分搬运只会更糟。它继续用于需求侧的描述性叙述。

### 2.3 交叉映射表继续做，用途改为标注

BO-4 的映射表**不取消**——它现在是「这个分区主要是哪几个 ward」这句话的依据，
而不是换算的工具。产出要求随之变化：

- 必须带**权重列**（工单加权份额），且**必须显式记录主导份额**；
- 下游任何**单值查表**都是错误用法，代码评审时按缺陷处理；
- 表仍然进 `dim_geography`（三种归属并存），schema 不变。

## 3. 后果

### 3.1 需要补一个数：分区 × 事件的非零率

任务 1 交付的 **77.9%** 非零率是在 **ward × 事件**（15 × 100 = 1,500 格）上算的。
换单元之后，M1 面板的真实密度**没有测过**：

- 单元数从 15 涨到 22（+47%），每格的平均工单量必然下降；
- 但事件数在排班期只有 59（顺位只在排班期存在），格数 1,298 反而少于 1,500。

**这个数必须补测**，判据沿用 design §3.3 任务 1 的 ≥ 70%。
补测入口：`snowfall_events` 的面板统计改按分区聚合，或直接在
`score_collinearity` 的 1,298 格上统计非零比例（它已经算出每格工单量）。

> **这不是可选项。** 本 ADR 换掉了 M1 的建模单元，而 M1 成立的判据正是非零率——
> 在旧单元上达标不蕴含在新单元上达标。**未补测前，M1「按原设计成立」这句结论
> 只对 ward 面板有效。**

### 3.2 «AI-Driven» 的落点不变

M1 仍然是「从降雪预报预测各单元的冬季工单量」，模型形态、特征、监督信号都不变，
变的只是行的定义。摘要里没有任何一句把预测单元钉死在 ward 上（§0.2 的映射表逐条
对应可查），因此不触发改摘要。

### 3.3 三个无排班分区的处理不变

`B/D` / `X` / `Downtown` 共 8,673 件工单（占落入分区总量 6.5%）没有顺位。
统一到分区之后它们仍然在面板里、仍然有请求量与天气，只是 `rank_factor` 为 NULL
——**不得填 0**（现有实现已如此）。这条约束在 ADR 0008 §3 已定，本篇不改。

⚠️ 开放项「`B/D` 到底是什么」因此**升级为阻塞项**：它单独占 4.7% 的地址，
而现在它是面板里的一整行。判错方向会同时影响 M1 的训练集与 BO-6 的输出。

### 3.4 对外叙事损失一个可讲的单元，但可控

ward 是选区，有名字、有议员、听众有代入感；分区是字母代号（A–V），天然难讲。
缓解方式是 §2.2 允许的标注：讲 `C` 区时说「主要覆盖 X、Y 两个选区」，
份额从映射表里读，**说出份额本身也是诚实的一部分**。

真正不能做的是为了好讲而把数搬到 ward 上——那是拿 66% 的误差换一个称呼。

### 3.5 Silver 与 Gold 的连带影响

- `dim_geography` 的分区几何**必须先 `ST_MakeValid`**（25 个里 8 个含 OGC 非法几何），
  并记录修复前后面积差。这条现在是关键路径上的前置，不再是「注意事项」。
- `fact_*` 的聚簇键按分区，不按 ward。
- 需求侧的描述性表可以继续按 ward / neighbourhood 建，但 `neighbourhood`
  必须 casefold（237 而非 242），否则 McMillan 会被拆成两个报告单元。

## 4. 被否决的方案

### 4.1 统一到 ward，顺位按地址数从分区摊过去

**否决理由：把误差加在最承重的那条腿上。**
顺位是这次复检里唯一实测**完全独立**的因子（`r` 与另两项都在 ±0.02 内），
也是实际影响最大的因子（0.300 分数单位）。摊到 ward 之后：分区间极差 2.2 个班次
会被平均掉一大半，方差下降，而 BO-6 里它的 0.30 权重是按未摊平的方差定的。
换言之，摊平之后**权重要重定，BO-6 的独立性结论要重测**——代价远高于换单元。

好处（ward 好讲）已由 §2.2 的标注方式拿到大半，不值这个价。

### 4.2 保留双单元，把映射误差写成 BO-8 的显式不确定性

**否决理由：最诚实，但在 H1 的时间盒里做不完，且讲不清。**
要诚实地表达 66% 的分派误差，得给每条推荐配一个不确定区间，而那个区间的宽度
会盖过推荐本身的差异——听众得到的信息是「这个方法回答不了这个问题」。
真要走这条，得先有一套误差传播的方法论，那是 H2 的工作量。

保留这条路作为**后备**：若 §3.1 的补测发现分区 × 事件非零率显著低于 70%
（即换单元反而伤了样本量），重开本决策时它是第一顺位的替代方案。

### 4.3 找一套 ward 多边形，用几何而非文本做 ward 归属

**否决理由：取不到数据，且它解决的不是这个问题。**
目录里 `tz8z-hyaz`（当期）/ `au4g-xjwh`（2017–2021）/ `mjit-gete`（2013–2017）
三套边界，SODA 与 geospatial export **都返回 `not_found`**（2026-08-09 实测）。

即便取到了也不改变结论：34.1% 测的是**两套划分嵌不嵌套**，
用几何 ward 重测只会让这个数更准，不会让它变大。ward 与作业分区不嵌套
是划分本身的性质，不是标签质量问题。

### 4.4 推迟决策，等 Silver 建好用 SQL 再看

**否决理由：Silver 的建表就是这个决策的产物。**
`fact_*` 的粒度、聚簇键、`dim_geography` 的连接方向全都由分析单元决定。
先建 Silver 再定单元，等于建完再重建一次。

uv run python -m scripts.analysis.score_collinearity
