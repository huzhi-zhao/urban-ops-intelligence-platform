# 数据体量基线（实测）

> **2026-07-29 实测。** 数字来自真实调用 SODA API 取样后本地序列化测量，可复现。
> 用途：容量规划、压缩策略决策、SLA 行数基线的输入。
> 数据源本身的字段与语义剖析见 [requirements/winnipeg-data-sources.md](requirements/winnipeg-data-sources.md)。

---

## 1. 测量方法

对每个数据集取 1000 行样本，按管道实际写入格式（NDJSON，紧凑分隔符）序列化，
测量原始字节数；再以 `gzip -9` 压缩后测量。

```bash
curl -s "https://data.winnipeg.ca/resource/<id>.json?\$limit=1000" -o sample.json
# 序列化为 NDJSON 后测 len()，再 gzip -9 对比
```

样本按门户默认顺序取，未分层抽样。对字段填充率差异大的数据集（如 311，
地理字段仅 20.9% 填充）这会带来偏差，故下表对 311 的单行字节数已按填充率上修。

---

## 2. 单行体量

| 数据集 | 字节/行（NDJSON） | 字节/行（gzip） | 压缩比 |
|---|---|---|---|
| `g3p4-h83y` Snow Clearing Status | 774 | 77.6 | **10.0×** |
| `u7f6-5326` 311 Requests | 486（均值上修至 ~517） | 87.1 | **5.6×** |

清雪状态压缩比高达 10 倍，因为它是地址簿式数据：`street_name` / `street_type` /
`postal_code` 高度重复，且三个布尔状态列基数极低。

311 压缩比较低，因为 `case_id` 是 64 字符哈希串、`interaction_id` 是长数字串，
两者近乎随机，不可压缩，合计占每行约三分之一。

## 3. 全量与年增量

| 项 | 未压缩 | gzip |
|---|---|---|
| 311 全量 18,346,621 行（一次性回填） | 9.5 GB | **1.6 GB** |
| 清雪快照 237,867 行 × 每日 | 184 MB/天 → **67 GB/年** | 18.5 MB/天 → **6.7 GB/年** |
| 供给侧（418 排班 + 49 禁令 + 边界几何） | < 5 MB | 忽略 |
| Open-Meteo 18 年日粒度 | < 1 MB | 忽略 |

Silver 层（Parquet + snappy）估算：311 全量约 1.0 GB（低基数文本列字典编码收益大）；
清雪快照若逐日存全量约 2.6 GB/年。Gold 层为聚合表，< 100 MB。

**综合年增量：约 10 GB/年（压缩后）。**

---

## 4. 结论

1. **gzip 是前置条件，不是优化项。** 清雪快照未压缩 67 GB/年 vs 压缩 6.7 GB/年，
   十倍差距全部来自一个默认配置。据此决定 Bronze 数据文件采用 `.ndjson.gz`——
   含一个必须注意的扩展名陷阱，见
   [ADR 0006](adr/0006-storage-compute-query-stack.md) §4.1。

2. **快照的日间冗余极高，是未来的优化空间。** 23.8 万行中每日实际变动的只有
   `has_street` / `has_alley` / `has_walk` 三个布尔位。Silver 层若改存 delta
   而非逐日全量，年增量可从 9.3 GB 降到 7 GB 以内。**当前不做**——Bronze 保持
   原始全量不可变是红线，Silver 的 delta 化属于用得上时再做的优化。

3. **只有快照需要流式写入。** 23.8 万行是一个不可切分的单文档，全量物化为 Python
   对象的内存占用远超其 184 MB 的序列化体积。而 311 的 1,835 万行看似更大，但回填
   按天切片，18 年摊下来平均每天约 2,800 行，每片都很小。约束的是**单文档大小**，
   不是总行数。

4. **年增量为容量规划提供了可外推的斜率。** 10 GB/年、且主要由快照的固定日增量
   构成，因此是线性的、可预测的，不随 311 历史回填完成而变化。

5. **容量不是约束。** 存储节点为本项目专用，100 GB 磁盘、当前可用 90 GB，
   按上述斜率约合 9 年余量。首年占用中一次性的 311 全量回填（1.6 GB）不到快照
   年增量（6.7 GB）的四分之一——**长期占用由快照主导**，容量若真成为问题，
   优先手段是结论 2 的 Silver delta 化，而不是清理历史。
