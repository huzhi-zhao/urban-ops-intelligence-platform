# 政策文件考古探针：除雪街道分级的成文依据

> **Status**: Accepted · **Date**: 2026-08-31

## 1. 问题

平台对「除雪优先级」的全部表述，目前建立在**一句没有出处的转述**上。

[business-objectives.md](../requirements/business-objectives.md) §987 写着
「除雪优先级不是靠经验，是政策规定的：主干道 P1 → 次干道 P2 → 住宅区 P3，
有法定时限」，§1176 据此把「跨优先级的调度建议」整个划出项目范围——
**这是一条承重的范围约束**，BO-8 只提供「同优先级内部谁先」这层边际信息，
理由就是那句话。§1325 另记着一条至今未做的待办：
「提取官方 P1/P2/P3 承诺时限」。

但仓库里**没有任何一处给出这句话的出处**。它是对的可能性很高，
可它现在的地位与 `shift_end` 被推翻前完全相同：**看上去理所当然，没人查过原文。**
[ADR 0008](../adr/0008-plow-schedule-is-a-plan-not-a-record.md) 的教训是
「字段确实存在，但由它定义的指标不存在」；这里的对应风险是
**分级确实存在，但它未必是我们以为的那套东西**。

已经能看到一个具体的口径冲突：

| | P1 / P2 / P3 | `shift_number` |
|---|---|---|
| 分的对象 | **街道**（主干道 / 次干道 / 住宅街） | **作业分区**（`plow_zone`） |
| 几何 | 线（路段） | 面（多边形） |
| 出处 | 城市政策文件（**未查证**） | `tix9-r5tc` 的一列（已实测） |

两者相关但不是同一套东西，而平台的分析全部建立在后者上。
在任何对外表述里把两者混用，是把一个**未经查证的政策概念**
安到一个**已实测的数据列**上——这正是 §1 开头那类错误的形状。

> ⚠️ 本篇列出的所有「未查证」，依据是**仓库中没有给出出处**，
> 不是「已经查过、确认有问题」。探针的结论可能是「那句话完全正确」——
> 那也是产出，而且是把 §1176 那条范围约束从转述升级为引证的产出。

## 2. 约束

| 约束 | 内容 |
|---|---|
| **时间盒** | **3 小时，不续期**。拆分见 §3.4。续期需要一个具体理由（例如已定位到文件但要跨文件追修订史），那属于下一轮，不属于本轮 |
| **不是数据查询** | 目标物是 PDF 与会议记录，**不在任何开放数据集里**。不打 SODA、不碰 Silver、不碰 MinIO |
| **不产生代码** | 本次不新增 job、不新增源、不改 schema。契约自 2026-08-13 冻结 |
| **逐字引用** | 结论一律**英文原文逐字**，附出处页码。**任何需要概括才能上屏的东西，等于没查到**——这是本篇最硬的一条 |
| **上游会消失** | 市政网站改版、撤稿、换链接是常态。**本地快照是这条链路的 Bronze 层**，没有快照的结论不成立（§3.3） |
| 显式接受的风险 | 三小时查不到任何一手政策文件。**「未命中」是合法交付**，见 §5 |

🔴 **不做「对表」那半截。** 「当年的假设今天还成立吗」需要通勤 OD 数据
（普查通勤矩阵或手机信令），四个在用源一条通勤记录都没有；
历史版分区边界同样没有（`39ur-higg` 是覆盖式发布，只有当前一版）。
本探针**只做考古，不做推论**。理由与 BO-1 被踢出主线是同一条：
一个无真值校准的推断，讲出来比不讲更贵。

## 3. 方案

### 3.1 三个问题，冻结后再开查

先写死清单再动手，是本探针与「想起来查一句」的唯一区别。**不许扩项。**

| Q | 问题 | 达标判据 | 它解开仓库里的哪一处 |
|---|---|---|---|
| **Q3** | P1–P3 街道等级的**官方定义** | City 自己的措辞，逐字 | §987 那句转述的出处；口径冲突（§1）的裁决依据 |
| **Q1** | 分级制度的**建立年份** | 一个年份 + 一份可引用的一手文件 | §987「是政策规定的」的成立时点 |
| **Q2** | 当年写下的**理由原话** | 一段可直接引用的英文 + 出处页码 | 无（纯背景，见 §5 的处置差异） |

🔴 **顺序是 Q3 → Q1 → Q2，不是编号顺序。**
Q3 独立于 Q1/Q2 的成败：Q1/Q2 全军覆没，Q3 的答案照样要用——
它是 §987 与 §1176 的出处，而那两处**已经在指导范围决策**。
Q1/Q2 只是背景，失败时的处置是「删掉」而非「重做」，因此排在后面。

顺带：若 Q3 的文件同时给出**承诺时限**，§1325 那条待办一并结清，
但**不因此扩大检索范围**——它是顺手，不是目标。

### 3.2 源清单，按一手性排序

排序即优先级。**一手性决定结论能不能被引用**，不决定它是否有趣。

| # | 源 | 一手性 | 能中哪几问 |
|---|---|---|---|
| 1 | City of Winnipeg 正式 **Snow Clearing / Ice Control Policy** | 一手 | Q3 + Q1 + Q2，一次全中 |
| 2 | **Public Works Committee / Council 的报告与会议记录** | 一手 | Q1 + Q2（修订史在这里） |
| 3 | City 的 winter maintenance **公众页** | 二手措辞 | Q3（🟡 可用于定义，**不可用于成因**） |
| 4 | 省级 / 学术的 winter maintenance 综述 | 旁证 | 🔴 **不作 Q1/Q2 的答案**，只作对照 |
| 5 | 新闻报道 | 🔴 **不可引用** | 仅用于定位第 1–2 类文件的年份或编号 |

### 3.3 每条证据的记录格式

这是「可重跑」的载体。字段少一个，三个月后就无法自证。

```
Q<n> | 状态: 命中 / 旁证 / 未命中
      引文: "..."            ← 逐字原文，不转述、不翻译
      出处: 文件名 · 页码 · URL
      检索日: YYYY-MM-DD     ← 与 URL 同等重要，上游随时会变
      一手性: 一手政策 / 委员会报告 / 公众页 / 综述 / 新闻
      快照: var/research/snow-policy/<文件名>.pdf
```

`var/research/` 与 `var/probe-cache/` 同待遇：**未跟踪**，删了就是重取。
不进 git 的理由是体积与版权；**但没有快照的引文不得进入产出物**——
链接会烂，引文不会。

### 3.4 人机分工：**两个切换点，不是六个**

原稿把整个检索默认成人工活。**那个假设是错的**——本会话有 `WebSearch` /
`WebFetch`，段 A、B 的检索、精读、摘引、存快照全部机器可做。
重排的空间几乎全部来自这一条。

分工判据只有一句：**只有人能做的才给人**。剩下的即使人做得更快也归机器，
因为瓶颈不是单步耗时，是**切换本身**——每次交回人手，人要重建一次上下文，
而这轮时间盒总共只有 3 小时。

| 只有人能做 | 为什么机器做不了 |
|---|---|
| 判定「这份文件够不够格当一手依据」的边缘情况 | 一手性是**责任判断**，不是文本特征 |
| G4 改 `business-objectives.md` 的签字 | 改的是承重的范围约束（§1176），不能自动落 |
| 需要登录 / 验证码 / 电话索取的门 | 机器过不去 |

其余**全归机器**：检索、下载、OCR、逐字摘录、快照落盘、台账填写、
未命中时的检索轨迹记录。

#### 三个批次，人只出现在头尾

```
H0 人 · 批准，即走
   └──► M 机器 · ~3 小时 · 无人值守，中途不问
          └──► H1 人 · 20 分钟 · 一次坐下，把所有判断一起做完
```

| 批 | 谁 | 时长 | 做什么 | 出口 |
|---|---|---|---|---|
| **H0** | 人 | 5 min | 批准本篇——门禁与字段要求随之冻结 | Status: Accepted |
| **M** | 机器 | ≤ 3 h | 段 A 定位（60）→ 段 B 精读摘引存快照（90）→ 段 C 填台账与裁决草案（30） | launch §3 台账填满，§4 门禁 G1–G3、G5 自评 |
| **H1** | 人 | 20 min | 一次性做完全部人类判断：一手性边缘裁决 · Q3 是否触发 G4 · 是否采纳 Q1/Q2 · 开放项状态 | 裁决定稿，G4 视结果执行 |

🟢 **本轮不走任何私人渠道索取文件。** 判据是可检验的：若存在一份方便转交的
一手文件，它早该主动到手了。**探针只查公开可检索的一手来源**——
这同时保证了结论的可复核性：私人转交的 PDF 无法被第三方按 §3.3 的 URL 复现。

🔴 **M 批中途不向人提问。** 遇到需要人判断的分叉，**两条都记下来**并在
launch §3 标 `⚠️ 待 H1 裁决`，继续往下跑。中途提一个问题的代价，
是把一次 20 分钟的集中评审换成三次 10 分钟的打断，总成本更高而结论不会更好。

#### 段内出口判据（M 批自己执行，不回头问）

| 段 | 出口判据 |
|---|---|
| A | 一份第 1 类政策文件都没定位到 → **当场判 Q1/Q2 未命中**，剩余时间全给 Q3。不延长 A |
| B | 每条证据填满 §3.3 的六个字段；字段填不满的证据**丢弃，不降格保留** |
| C | 当天完成，不隔夜。隔夜的代价是把「查到了什么」换成「记得查到了什么」 |

#### 预检：M 批开跑前 60 秒

出站走代理，`WebFetch` 对市政站点可能被拦。**M 批第一件事是拿一个已知
URL 试一次**：通 → 按上表跑；不通 → **立即停，退回 H0 让人决定**
（人工取文件后机器接手摘引，或整轮改期）。
🔴 不要在不确定网络能力的情况下跑满三小时再报告失败。

## 4. 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 一并做「对表」（今天与当年比哪里不一样） | 需要两个时点的分区边界 + 通勤 OD，**两样都是零行**。见 §2 |
| 为通勤故事接入路网 `ngsx-caav` | BO-2 那轮已按 design §6 的条件触发规则**判定不需要接**。为一个讲不成的推论去接一个刚判定不需要的源，是往回走 |
| 把结论直接改进 `business-objectives.md` | 探针**只产出结论**（同 20260808 篇的约束）。改 BO 是下一个任务，且要逐条评估——查到不等于当场改 |
| 产出物另开一篇 `requirements/` 文档 | 本次只有三行结论，一篇常青文档撑不起来，且 `docs/README.md` 目标是 ≈20 篇、**宁合勿拆**。证据台账落 launch §3 |
| 不设时间盒，查到为止 | 「想起来查一句」的病根不是不勤奋，是**没有终止条件**——不知道查到什么算完，也不知道查不到什么时候停 |
| 允许中文转述上屏 | 转述是编造的最短路径。一条逐字引文的信息量，高于三段「大意是」 |

## 5. 验收判据

本探针的判据不是「查到了」，是**三个问题各自落到一个明确状态**。

| 判据 | 内容 |
|---|---|
| G1 | Q1 / Q2 / Q3 **各有一行裁决**，状态 ∈ {命中, 旁证, 未命中}，无空缺 |
| G2 | 每条「命中」附齐 §3.3 的六个字段，**逐字引文非空、快照文件存在** |
| G3 | 无任何一条结论的一手性为「新闻」（§3.2 第 5 类禁令） |
| G4 | Q3 命中 → `business-objectives.md` §987 的转述补上出处（**单独一次改动，附引文**） |
| G5 | 全程 ≤ 3 小时，超时即按当时状态收尾 |

三种裁决的处置**各不相同**：

| 裁决 | 处置 |
|---|---|
| **命中** | 引文入 launch §3 台账；Q3 另触发 G4 |
| **旁证**（有说法，无一手原文） | 🔴 **不得引用为成因**。Q3 退回「只用公众页的定义措辞」，Q1/Q2 按未命中处理 |
| **未命中** | ✅ **合法交付**。写明查了哪五类源、各自为什么没有，**不拿推测填缝**。§987 那句转述维持原状并标注「出处未查证」 |

🔴 G4 是本次唯一会改动仓库既有文档的动作，**且只在 Q3 命中时发生**。
Q1/Q2 无论结果如何都不改任何既有文档——它们是背景，不是依据。
