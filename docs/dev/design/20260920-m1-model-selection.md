# M1 模型选型与评估协议改造

> **Status**: Draft · **Date**: 2026-09-20

H2 的第一件事。分两部分：**先修评估协议**（第 3 节 A 批），**再跑模型对照**
（B 批）。顺序不可换——理由见第 1 节。

前置阅读：[20260820-scoring-chain-and-m1.md](20260820-scoring-chain-and-m1.md) §4 与 §8，
[launch/20260820-scoring-chain-and-m1-launch.md](../launch/20260820-scoring-chain-and-m1-launch.md) §3.3。

---

## 1. 问题

### 1.1 M1 的选型有论证，没有实证

L3-a 交付的 M1 是 Poisson GLM（`log(unit_size)` 作 offset）。这个选择**有记录**：
design §8「被否决的选项」写了 `M1 用梯度提升起步` 的否决理由（目标是计数 ·
面板 2,178 格 · 要可解释且要与基线成对汇报），`models/request_forecast/model.py`
的模块 docstring 还写了升级路径（输给基线则上 negative binomial 或 GBM，
**必须换 `model_version`**）。

缺的不是流程，是**对照**：除 GLM 外没有第二个模型真的在这份面板上跑过。
因此「GLM 在这个规模上够用」目前是一条**论证**，不是一条**证据**。

H1 期间这是正确的取舍（关键路径上先跑通）。H2 没有这个借口。

### 1.2 🔴 但对照实验现在做不了——评估协议分辨不了模型

`model.py::split_holdout_last_season` 留出**最近一个雪季 = 7 个事件**
（launch §3.3 第一条保留）。在这个留出集上：

- 目标高度零膨胀（25 分位 = 0），1,298 个排班期格里 908 个非零；
- 折间方差几乎必然**大于**模型之间的差异。

现有的 `MAE 7.345 vs 基线 23.628` 是对**基线**的差距，基线（因果扩展均值）
是一个很弱的对手。GLM / NB / GBM 相互之间的差距会小一到两个量级，
**7 个事件分辨不出来**。

在这个协议上跑五个模型选最优，选出来的是噪音。所以 A 批必须先做。

### 1.3 两个指标都只量「水平」，而下游消费的是「排序」

`evaluation.metrics` 是 `mae` + `poisson_deviance`，两个都是水平指标。
而 BO-8 消费的是**事件内分区排序**，不是绝对量。

这不是推测，是已实测的结论：天气项方差 **99.4% 在事件之间、仅 0.6% 在事件之内**
（探针任务 3）——它决定评分高低而几乎不影响事件内排序。同一份数据上
「预测得准」和「排得对」是两件可以分开的事，而现在**没有任何一个指标能看见后者**。

后果是可构造的：一个模型可能 MAE 更好但排序更差，按现有协议会被选中，
而按 BO-8 的口径它更差。

## 2. 约束

- **不引入新数据源。** 本篇的全部候选都只吃现有面板。
- **schema 冻结。** F5 只有一个 `predicted_count` 列（contract 自 2026-08-13 冻结）。
  任何新模型的产出必须能落进现有 F5 形状，否则走变更流程。
  `weighted_request_count` 作为第二目标是 `config/models/m1.yaml` 明写留给 H2 的，
  但它需要改 schema，**不在本篇 A/B 两批内**。
- 🔴 **`shift_number` / `rank_factor` 对所有候选模型一律禁为特征**
  （`features.FORBIDDEN_FEATURES`，单测钉死）。顺位是 BO-6 权重 0.30 的独立第二项，
  混进权重 0.40 的请求量项会让三项独立性的实测结论（`r = +0.017`）失效。
  **换模型时这条最容易破**——GBM 少写一个 `drop` 就进去了。新模型必须复用同一条断言。
- **多版本共存的基建已经就位**：F5 的 artefact 方案（`gold/_forecast_runs/{model_version}/`）
  实测两版本共存 2,596 行、v1 重建前后逐位相同。每个候选一个 `model_version`，
  不需要新建任何东西。
- 计算节点 7 GB 可用内存。面板 2,178 行，所有候选都在单机分钟级，**不构成约束**。
- 面板规模是硬上限：22 个分区 × 99 个事件。**数据量不会因为换模型而变多**，
  这是选择"小模型 + 强正则"而非"大模型"的物理原因。

## 3. 方案

### A 批 —— 评估协议改造（先做，独立于模型清单）

改 `models/request_forecast/model.py` + `config/models/m1.yaml`，不碰 GLM 本身。
A 批跑完，GLM 的数字会**重新量一遍**，现有的 7.345 / 23.628 退为历史记录。

**A1 · 留一季交叉验证取代单一留出季**

`split.strategy: holdout_last_season` → `leave_one_season_out`。排班期 8 个雪季
逐个留出，每折内部复用现有的 `assert_no_history_leak` 时序检查（该函数不用改，
逐折调用即可）。

**A2 · 分组单位是事件，不是行**

同一事件内 22 个分区强相关。事件被劈到折两边即泄漏。折边界只能落在事件边界上，
而按季切天然满足——A1 的实现里显式断言一次，不靠"按季切自然就对"。

**A3 · 报折间标准差，并把它变成门禁**

🔴 **模型间差异小于折间 SD 即判定为「无差异」**，不得宣布赢家。
这条要写成可执行门禁而非文档约定，否则 bake-off 一定会选出一个"赢家"——
这是 L2/L3 反复出现的同一类失败（规则跑得动但问错了问题）。

**A4 · 新增排序指标**

每个事件内部：分区预测排序 vs 实际排序的 **Spearman ρ**，以及 **top-3 重合率**
（资源建议实际只看前几名）。与 MAE / deviance 并列汇报，**不合成单一总分**——
合成就把 1.3 节那个取舍藏起来了。

**A5 · 基线从一个扩到四个**

现有只有因果扩展均值。增加：**全零基线** · **分区历史均值** · **上一事件平移**。
零膨胀数据上「全零」有时意外地强，赢不过它是高信息量的结果。
`evaluate()` 的「两边同一批行」逻辑（`usable` 掩码）推广到 N 个方法，
这条不能松——不同方法在不同行集上打分不叫对照。

### B 批 —— 模型对照

A 批跑通后执行。每个候选一个 `model_version`，共用 A 批协议。

**第一梯队（回应已知的数据性质，必跑）**

| 候选 | 回答什么 | 成本 |
|---|---|---|
| **Negative Binomial GLM** | Poisson 假设均值 = 方差。311 计数几乎必然过离散；若离散参数显著 > 1，现有系数的标准误就是错的，**哪怕点预测还可用** | statsmodels 换 family，极低 |
| **Hurdle / 零膨胀 NB** | 直接对着「25 分位 = 0」。两段式 `P(有工单) × E[数量 \| >0]`，零的那一段本身是有用输出 | 低 |
| **分区随机截距的混合效应 Poisson** | 22 分区 × 99 事件、每分区样本少——**部分池化正是小样本面板的标准解**，理论上最贴这个数据形状 | 中（`PoissonBayesMixedGLM`） |

**第二梯队（探针，跑一次就够）**

- **LightGBM + Poisson objective**：2,178 行必然过拟合，必须折**内**早停 + 强正则
  （折外调参即泄漏）。价值不在上线，**在于给非线性信号量一个上界**——
  若重度正则的 GBM 也赢不了 GLM，「GLM 够用」就从论证变成了证据。这正是 1.1 节缺的东西。

**第三梯队（方向性，本篇只立项不排期）**

- **对排序直接建模**：既然下游只吃事件内排序，可预测「该分区占该事件总量的份额」
  （compositional / Dirichlet-multinomial），或直接用 learning-to-rank 目标。
  即「优化真正关心的量」，而非「优化水平、指望排序跟着好」。
- **Conformal prediction 给预测区间**：模型无关、成本近零、覆盖率有有限样本保证。
  对**公开表述**价值高——现在没有任何不确定性量化，而一个点估计在 7 个事件上是脆的。

### C 批 —— 不换模型的特征工作（可与 B 并行）

- 滞后只有一阶（`prev_target` / `expanding_mean`）。可加二阶、分区 × 月交互、
  雪季内进度（本季第几场雪）、节假日。
- `accum_flag` 在短面板里近似可分（`fit_poisson_glm` 把 `maxiter` 提到 200 就是为它）。
  **8 个 accum 事件撑一个二值特征是薄的**，值得单独检验其实际贡献。

## 4. 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 先跑模型对照，评估协议之后再改 | 7 个事件的留出集分辨不了模型间差异，选出的是噪音。且一旦宣布过赢家，改协议就变成"推翻自己的结论"，政治成本远高于现在 |
| 扩大留出季到两三个雪季 | 训练集本来就只有 8 个排班期雪季，再切走三个会让长历史训练这条 F1 契约失去意义。留一季 CV 用满全部数据且每折都有独立测试 |
| 把 MAE / deviance / ρ 合成一个总分 | 合成即把 1.3 节的取舍藏进权重里。BO-6 三项权重的教训正是「名义权重与实际影响序可以相反」；这里宁可并列汇报，由人取舍 |
| 引入新数据源（路网、人口、实时路况） | 本篇的前提就是「在没有更多高质量数据源的情况下」。路网 `ngsx-caav` 已按探针 design §6 的条件触发规则判定不需要接 |
| 直接上深度模型（LSTM / Transformer） | 2,178 行、99 个时间点。样本量比参数量小若干个量级，结果不可辩护，且违反「要能在 slide 上解释」这条自 §8 起就成立的约束 |
| 用 `weighted_request_count` 作第二目标 | 需要改 F5 schema，而 contract 自 2026-08-13 冻结。它确实是 `m1.yaml` 留给 H2 的，但要走变更流程，不搭本篇的车 |
| 把 `rank_factor` 加进特征"试试看" | `m1.yaml` 已明写禁止，单测钉死。会让 BO-6 三项独立性的实测结论失效 |
| 用随机划分做交叉验证 | 滞后特征使随机划分成为真实泄漏，不是技术细节。`assert_no_history_leak` 存在的全部理由 |

## 5. 验收判据

A 批：

- `make test-unit-offline` 全绿；新增单测覆盖「折边界落在事件边界上」与
  「差异 < 折间 SD 时不得判定赢家」两条。
- 对现有 GLM 跑完留一季 CV，产出 8 折的 MAE / deviance / ρ / top-3 与折间 SD。
  🔴 **预期结果之一是「GLM 与基线的差距在折间 SD 之内」**——若如此，
  `beats_baseline` 这个布尔字段的含义要跟着改，且 BO-8 §0.2.2 的禁语得到进一步佐证。
- 四个基线全部在同一批行上打分（`usable` 掩码推广后的断言）。

B 批：

- 每个候选一个 `model_version`，F5 artefact 多版本共存，`COUNT(DISTINCT model_version)`
  门禁照旧生效。
- 每个候选都通过 `FORBIDDEN_FEATURES` 断言。
- 一张对照表：候选 × (MAE, deviance, ρ, top-3)，每格带折间 SD。
- 🔴 **判据前置**：下面这条决策规则写在跑之前——
  **除非某候选在 ρ 或 top-3 上超出 GLM 一个折间 SD 以上，否则维持 GLM。**
  水平指标（MAE / deviance）单独变好不构成换模型的理由，因为下游消费排序。
