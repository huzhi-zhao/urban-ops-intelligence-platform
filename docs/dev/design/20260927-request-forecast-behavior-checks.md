# 请求量预测的常识与外推检查（H2-R3）

> **Status**: Accepted · **Date**: 2026-09-27
>
> **需求**：[H2 模型与评分层改进 §R3](../requirements/20260921-h2-model-and-scoring-improvements.md)
> · **前瞻消费者**：[H2-R12](20260927-forecast-chain-rehearsal.md)
>
> 本篇冻结检查口径，先于任何真实模型输出。它只判断模型行为是否值得警惕，
> 不用合成输入衡量准确率，也不因发现问题而自动改模型。

## 1. 问题

M1 是带 log link 的计数模型。训练与留出评估能回答历史误差，却不回答两件不同的事：

1. 固定其余信息时，降雪更多或气温更低，预测是否反而下降；
2. 降雪超过训练范围后，指数链接是否把一个有限输入放大成数量级跳变或非有限值。

R12 已能标记输入落在训练范围外，但故意不判断标记后的预测值。R3 补上这个判断，
并在 R11 使用真实冬季预报之前留下可复跑的模型版本产物。

## 2. 约束

1. **模型版本显式。** 命令必须指定 `model_version`，模型产物里的版本和面板指纹都要
   与输入匹配；不按目录顺序猜“最新版本”。
2. **只用训练侧作锚点。** 其余特征取模型实际拟合过的每一行，留出季不参与锚点或
   训练范围计算。这里不需要标签，但不能让测试范围由答案侧决定。
3. **一次只动一个特征。** 每个锚点的其他特征、lag 和 `unit_size` 全部固定。
   `total_snowfall_cm` 变化时不联动重算 `severity_score`；否则无法区分是哪一项造成行为。
4. **发现不是门禁。** 单调性违反或外推放大达到界线时，产物记录 finding，进程仍成功。
   自动失败会诱导人去调阈值直到变绿，违背本条“检查并如实报告”的目的。
5. **不改 schema。** 结果随模型版本写在 `gold/_forecast_runs/{model_version}/` 的 artefact
   目录；不进入 Gold 表，也不改变 F5。
6. **不评价准确率。** 合成输入没有真实工单数，输出只能与相邻合成输入比较行为，
   不能出现“准”“误差”“优于基线”等表述。

## 3. 方案

### 3.1 单调性

在训练侧每一行上各做两条 one-at-a-time 扫描：

| 被改变的特征 | 输入顺序 | 期望的预测顺序 |
|---|---|---|
| `total_snowfall_cm` | 训练最小值 → 最大值 | 不下降 |
| `min_temperature_c` | 训练最大值 → 最小值（越来越冷） | 不下降 |

每条扫描在闭区间上取 **9 个等距点**，包含两端。相邻预测的相对下降超过
`1e-12` 才记为违反；该容忍度只吸收浮点误差，不允许有业务上可见的逆向变化。

检查覆盖训练侧全部锚点，不挑一个“代表性分区”。产物记录锚点数、比较次数、违反次数、
非有限预测数和最大相对下降。任何违反都是发现；不在 R3 内修改系数、特征或 family。

### 3.2 外推

外推只改变 `total_snowfall_cm`。对每个训练锚点分别计算：

- 边界预测：降雪量设为训练侧历史最大值；
- 极端预测：降雪量设为历史最大值的 **2 倍**；
- 放大倍数：极端预测 ÷ 边界预测。

“爆炸”在看结果前定义为以下任一项：

1. 任一预测为 `NaN`、正负无穷或非正值；
2. 任一锚点的放大倍数 **大于 100**。

两倍降雪导致超过两个数量级的响应变化，已经足以让前瞻页面的数值失去操作意义；
这个相对界线不依赖分区大小，也不会把“一个大分区本来就有更多工单”误判成爆炸。
产物同时记录最大绝对预测供人阅读，但绝对值不参与判定。

### 3.3 产物与入口

入口接收原始面板、目标版本的 `metrics.json` 和独立配置
`config/models/m1_behavior.yaml`。输出：

`gold/_forecast_runs/{model_version}/behavior_checks.json`

文件包含模型族、版本、面板指纹、留出季、冻结参数、每项检查的完整计数及 findings。
它不带运行时钟；相同输入重复运行应得到逐字节相同的 JSON。

## 4. 被否决的选项

1. **只看系数正负。** 当前 GLM 上近似等价，但未来 family 或变换改变后不再成立；R3 检查的
   是公开输出行为，不是某一种实现的内部参数。
2. **降雪变化时重算严重度。** 同时改变两个有共线性的特征，发现逆向时无法归因；相干天气
   情景属于 R12/R11，one-at-a-time 常识检查不承担它。
3. **用合成工单数计算误差。** 没有观察答案，只能让模型自己给自己出题并判卷。
4. **把 finding 设为非零退出码。** R3 明确要求“违反即为发现，记录不改模型”；结构错误
   才失败，行为发现不失败。
5. **按预测工单绝对值设上限。** 分区规模不同，绝对上限会把 offset 的正常作用误判为风险。

## 5. 验收判据

- 两项单调检查均覆盖训练侧全部行和 9 点网格；其他特征与 offset 逐行固定。
- 人工设置错误符号的系数时，单测能分别抓到降雪与低温的逆向行为；正确符号时无误报。
- 两倍历史最大降雪的最大响应倍率、最大绝对预测和所有非有限值均被记录；
  `>100×` 与非有限预测会生成 finding，恰好 `100×` 不生成。
- `model_version` 或 `panel_fingerprint` 不匹配时在检查前拒绝。
- 行为 finding 返回成功；配置、版本、面板或系数结构错误返回失败。
- 相同输入重复运行产生相同 JSON；不写 Gold / Silver，不上传时不访问对象存储。
- `make lint`、`make test-unit`、`make test-ml` 全绿。

## 6. 开放项

R1 若选择新的 serving family，同一个 R3 入口对该版本重跑。只要产物仍交付 log-link 的
均值系数，检查算法不变；若模型不再能由系数直接推断，应增加显式 adapter，不能回退到
Poisson 或沿用旧版本结论。
