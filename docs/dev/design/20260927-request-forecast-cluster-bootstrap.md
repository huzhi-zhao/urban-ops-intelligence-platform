> · **上线记录**：[20260927-request-forecast-cluster-bootstrap-launch.md](../launch/20260927-request-forecast-cluster-bootstrap-launch.md)

## 1. 问题

M1 目前只交付一个点估计。事件内排序却常由很小的预测差决定：伞篇实测同班次相邻格
的 `load_score` 分差中位只有 0.106，而 M1 留出季 MAE 是 7.345 张工单。两者量纲不同，
不能直接比较；必须把「只有这些历史事件」造成的抽样不确定性传播到每个事件 × 分区的
预测，才能判断一个前 K 名是否在历史轻微变化后仍成立。

Poisson GLM 的解析区间不解决这个问题。项目已知目标过度离散，且同一降雪事件的 22 行
共享天气与时间背景，不是 22 个可交换的独立观测。按行重采样会同时破坏面板相关结构和
`prev_target` / `expanding_mean` 的时序定义。

R13 因而交付原始重采样预测副本。R6 再从同一批副本计算任意 K 的排名稳定性、区间和
复核提示；不把某一个阈值提前烘焙进模型产物。

## 2. 约束

1. **簇是事件。** 一个事件的全部分区行一起被抽中、一起重复或一起缺席；不按行、分区、
   班次或季节重采样。
2. **特征固定。** 真实面板上先计算一次日历与 lag 特征，重采样循环不得重新计算它们。
   本轮明确不覆盖 lag 特征自身的不确定性。
3. **留出边界不动。** 重采样对象是被扰动 `model_version` 真正用于拟合的训练侧，不得把
   留出季答案放回拟合。生产口径是：99 个原始事件，去掉第一个无 lag 事件后剩 98 个，
   再留出最近一季 7 个，故每个副本从 **91 个训练事件**有放回抽取 91 次。伞篇的 59 个
   事件是页面/排名的排班期输出范围，不是拟合样本。
4. **预测面板固定。** 每个副本都在真实的排班期面板上预测，生产口径为
   **59 × 22 = 1,298 格**；不在抽样面板上预测。
5. **点估计不换。** 页面中心值继续来自 F5 的 `predicted_count`。自助副本只提供不确定性，
   不用副本均值或中位数静默替换已冻结的点估计。
6. **模型版本显式。** R13 产物写入既有
   `gold/_forecast_runs/{model_version}/`，不建 Gold 表。执行时必须显式给出版本，并验证
   版本指纹与输入面板一致。
7. **不改 M1 指纹。** 副本数和随机种子放在独立的 `m1_bootstrap.yaml`，不得加入
   `m1.yaml`；后者整体参与 `model_version` 指纹，加入运行参数会把同一个模型伪装成新版本。
8. **失败不可被平均掉。** 任一副本不收敛、系数非有限或预测非有限时整次运行失败并报告
   `replicate_id`。静默丢弃困难副本会选择性缩窄区间。
9. **当前无生产面板随仓库分发。** 代码与单测可以离线完成；生产 500 副本必须使用计算
   节点导出的真实面板，不能拿合成 fixture 代替实测。

## 3. 方案

### 3.1 两层产物

模型层对每个 `model_version` 写三个追加文件：

| 文件 | 内容 |
|---|---|
| `bootstrap_predictions.csv` | `replicate_id, snowfall_event_id, plow_zone, predicted_mean`；每副本 1,298 行 |
| `bootstrap_coefficients.csv` | `replicate_id, term, estimate` |
| `bootstrap_metadata.json` | B、种子、簇单位、特征固定标记、模型族、面板指纹、训练簇数、预测格数、留出季与列契约 |

R6 的派生层读取冻结的 `FIG-BO8-03` 与上述文件，写
`FIG-BO8-03-uncertainty.json`。它包含每格的均值区间、请求数预测区间、
K ∈ {3, 5, 8} 的前 K 概率、默认复核提示、18 组阈值网格、稳健集和留出覆盖率。
该摘要是页面构建输入，不是新的证据查询，也不进入 Gold。

### 3.2 重采样算法

1. 读取与目标 `model_version` 相同的原始面板和 M1 配置。
2. 用现有 feature pipeline 在真实面板上计算一次全部特征。
3. 沿用 `holdout_last_season` 得到训练侧和留出侧。
4. 对 `b = 1..B`：
   - 从训练侧唯一事件 ID 中有放回抽取同样数量的 ID；
   - 按抽取顺序拼接每个 ID 的完整分区簇；
   - 用该副本重新拟合与 `model_version` 相同的模型族；
   - 在未经抽样的 1,298 格真实面板上输出响应均值；
   - 记录全部系数。
5. 输出按 `replicate_id, snowfall_event_id, plow_zone` 稳定排序。

默认 **B = 500**。随机数由固定根种子派生出逐副本种子，使一个副本失败时能单独定位，
也为以后安全并行保留边界。同一种子与输入在同一数值环境中必须复现相同抽样成员和预测。

### 3.3 排名、并列与复核提示

排名使用每千地址预测率，而非预测总量：

`predicted_mean / address_count × 1000`

每个副本、每个事件内按该率降序排列；精确并列以 `plow_zone` 升序作公开且确定的
tie-break，并在元数据记录。每格在前 K 的副本数除以 B 即排名稳定性。

默认提示仍由 R6 的预登记参数决定：K = 5、S = 4、P = 0.8。提示必须同时满足点估计率
进入前 K、计划班次 ≥ S、前 K 稳定性 ≥ P，且 `fit_role = holdout`。样本内格提示恒为零。

稳健性分析扫描 K ∈ {3, 5, 8} × S ∈ {4, 5} × P ∈ {0.7, 0.8, 0.9} 的 18 组，
输出每组提示数和全部 18 组共同命中的格；不从结果中挑一组称为“最好”。

### 3.4 区间

原始副本的分位数是**预测均值区间**。页面与实际请求数并排展示的是**请求数预测区间**：
对每个副本均值再从该 `model_version` 的计数分布抽一个请求数，实现参数抽样与过程噪声的
共同传播。区间水平在看结果之前固定为 **90%（P05–P95）**，并在 154 个留出格上报告
覆盖率。

当前 `m1-poisson-*` 版本按 Poisson 分布生成请求数。未来 R1 若交付负二项版本，元数据必须
同时携带它采用的离散参数，派生层才可按同族生成；缺参数时必须拒绝，不能回退成 Poisson。

### 3.5 分批与运行入口

1. 模型批：纯函数、CLI、三份 artefact、单测。
2. 派生批：区间、排名概率、18 组网格、覆盖率摘要、单测。
3. 页面批：把摘要接入既有 `#/zone` 骨架；摘要缺失时继续显示 `range pending`，不得泄漏
   裸点估计。
4. 生产批：真实面板跑 500 副本，核对门禁后上传到既有模型版本目录，再冻结摘要。

## 4. 被否决的选项

1. **按 2,002 行独立重采样。** 破坏事件内相关性，并把共享天气当成 22 份独立证据。
2. **重采样 59 个排班期事件。** 它不是现有 M1 的拟合集，得到的区间不属于该版本。
3. **把 7 个留出事件一起重采样。** 会让用于覆盖率与提示检验的答案进入拟合。
4. **在每个副本重算 lag。** 回答了一个更大、成本高一个量级的问题，不是本条冻结范围。
5. **只保存 P05/P95。** R6 每换一个 K 或 P 就必须重跑模型，无法完成阈值稳健性扫描。
6. **只交 Poisson 解析区间。** 已知过度离散下系统性偏窄，也没有传播事件抽样不确定性。
7. **副本失败后补抽到满 B。** 会隐藏失败样本并改变事先登记的随机序列。
8. **把副本落 Gold 表。** 当前只有页面一个消费者，且会无必要触发冻结 schema 的五步变更。

## 5. 验收判据

### 模型产物

- 生产训练侧恰好 91 个事件簇，每簇 22 个相同分区集合；留出 7 个事件不在任何拟合副本。
- `bootstrap_predictions.csv` 恰好 `B × 1,298` 行；B = 500 时为 **649,000 行**。
- `(replicate_id, snowfall_event_id, plow_zone)` 唯一；每副本覆盖相同的 59 × 22 真实面板。
- 每个副本输出同一组有限系数，所有 `predicted_mean` 有限且非负。
- 元数据的 B、完成数、种子、`cluster_unit=event`、`features_fixed=true`、模型版本、
  面板指纹、91 个训练簇、1,298 个预测格与留出季齐全。
- 相同输入与种子复跑得到相同抽样种子、键集合与数值结果；版本/指纹不一致在拟合前拒绝。

### 派生与页面

- 每格同时有原始 F5 点估计、90% 请求数预测区间和 K=3/5/8 的稳定性。
- 18 组网格全部求值，输出提示数分布与稳健集。
- 154 个留出格的预测区间覆盖率随摘要记录；不以是否达到 90% 作为调参开关。
- 样本内提示数 = 0；R2 前提示只可能出现在唯一有公开计划的留出事件的 22 格中。
- 摘要缺失时页面仍不显示裸点估计；摘要版本与显式服务版本不一致时构建失败。
- `make lint`、`make test-unit`、`make test-ml` 全绿。
